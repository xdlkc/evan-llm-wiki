# evan-llm-wiki

English | [简体中文](./README.zh-CN.md)

A generic, agent-maintained Markdown-first LLM wiki toolkit inspired by the Karpathy `llm-wiki` pattern.

Rather than treating a knowledge base as an ephemeral vector cache, `evan-llm-wiki` scaffolds a layered Markdown project and drives a deterministic, one-source-at-a-time maintenance loop:

1. Discover raw sources under `raw/_sources/` and record a plain-file queue in `wiki/_system/manual_queue.json`.
2. Pop one `pending` item at a time and invoke `codex exec` with a fixed prompt template (`wiki/_system/manual_runner_prompt.txt`).
3. Let Codex read the primary source (plus any local screenshots, charts, or diagrams that affect interpretation) and manually synthesize or update pages under `wiki/`.
4. Keep queue state, indexes (`wiki/index.md`), and append-only logs (`wiki/log.md`) in plain files.

## Target Project Assumptions & Rules

The toolkit uses Python 3 standard library scripts and assumes only that a target project stores raw inputs under `raw/` and durable compiled knowledge under `wiki/`.

### Expected Project Layout

Running `init` scaffolds the following structure in `--project-root`:

```text
<project-root>/
├── AGENTS.md                         # Canonical wiki maintenance rules (Codex)
├── CLAUDE.md                         # Claude Code instructions (points to AGENTS.md)
├── .codex/skills/llm-wiki/SKILL.md   # Skill used by `codex exec` during ingest
├── schema/
│   ├── policy.md                     # Frontmatter schema, attribution, body layout
│   └── workflows.md                  # Ingest / Query / Lint workflows
├── raw/
│   ├── _sources/                     # Read-only source directories or plain files
│   └── _attachments/                 # Supporting images, PDFs, CSVs, etc.
└── wiki/
    ├── 00_overview/                  # Corpus overviews
    ├── 01_entities/                  # Repeated entities (people, tools, libraries, orgs)
    ├── 02_concepts/                  # Durable cross-source concepts
    ├── 03_sources/                   # One curated page per ingested source
    ├── 04_projects/                  # Project-specific syntheses
    ├── 05_decisions/                 # Reusable conclusions, tradeoffs, lint tasks
    ├── _system/
    │   ├── manual_queue.json         # Queue state generated by --rebuild-queue
    │   └── manual_runner_prompt.txt  # Prompt template rendered per source item
    ├── index.md                      # Curated navigation index
    └── log.md                        # Chronological maintenance log
```

### Source Discovery & Operating Rules

- **Supported source formats**: Subdirectories in `raw/_sources/` (resolving primary text in order: `README.md`, `index.md`, `content.md`, `raw.md`, `raw.txt`, `raw_content.html`, or the first `.md`/`.markdown`/`.txt`/`.html`/`.htm` file) or top-level `.md`/`.markdown`/`.txt`/`.html`/`.htm` files directly under `raw/_sources/`.
- **Read-only raw layer**: Never modify files under `raw/`.
- **Single primary attribution**: Prefer one primary human-readable source in page frontmatter `sources` (if `README.md` exists, list only `README.md`). Auxiliary HTML, JSON, or attachments may be read for context without polluting `sources`.
- **Visual inspection**: Inspect screenshots, charts, and diagrams in the source directory when they materially affect meaning.
- **Manual synthesis over templating**: Pages under `wiki/` must be compiled from reading the source directly—never generated via scripts or mechanically templated from headings and titles.
- **Crash recovery**: Queue items transition `pending` → `in_progress` → `done` (or `failed`). Any leftover `in_progress` items are automatically reset to `pending` on the next runner invocation.

## Prerequisites

- **Python 3** (standard library only for the CLI and runner scripts)
- **Codex CLI** (`codex` on `PATH` supporting `codex exec`, required for live runs; `--dry-run` works without invoking `codex`)

## Quick Start

From a clone of this repository:

### 1. Initialize a target project

```bash
python3 scripts/llm_wiki_cli.py init --project-root /path/to/project
```

Pass `--force` to overwrite existing scaffolded rule/schema/template files (`init_llm_wiki.py` preserves existing files by default).

### 2. Add source material

Place sources under `/path/to/project/raw/_sources/`, either as:
- one folder per source containing `README.md`, `index.md`, `content.md`, `raw.md`, `raw.txt`, or `raw_content.html` (plus optional images/attachments), or
- standalone `.md`, `.markdown`, `.txt`, `.html`, or `.htm` files.

### 3. Build the queue and inspect with a dry run

> **Note on CLI entrypoints**: `scripts/llm_wiki_cli.py` currently exposes `init` and basic `run --run-once` / `run --run-all`. Queue management flags (`--rebuild-queue`, `--dry-run`, `--retry-failed`, `--only-source-id`, `--limit`, `--model`, `--codex-arg`, custom paths) live on [`scripts/llm_wiki_runner.py`](./scripts/llm_wiki_runner.py).

```bash
# Rebuild wiki/_system/manual_queue.json from raw/_sources/
python3 scripts/llm_wiki_runner.py --project-root /path/to/project --rebuild-queue

# Preview the next Codex command without modifying queue status or running Codex
python3 scripts/llm_wiki_runner.py --project-root /path/to/project --run-once --dry-run
```

### 4. Process items

```bash
# Process one pending item via unified CLI or runner
python3 scripts/llm_wiki_cli.py run --project-root /path/to/project --run-once

# Process all pending items sequentially
python3 scripts/llm_wiki_cli.py run --project-root /path/to/project --run-all

# Retry failed items or target a specific source_id via runner
python3 scripts/llm_wiki_runner.py --project-root /path/to/project --run-once --retry-failed
python3 scripts/llm_wiki_runner.py --project-root /path/to/project --run-once --only-source-id example-source
```

Useful runner flags in [`scripts/llm_wiki_runner.py`](./scripts/llm_wiki_runner.py):
- `--model <name>`: pass `--model <name>` to `codex exec`
- `--codex-arg <arg>`: repeatable extra argument forwarded to `codex exec`
- `--limit <n>`: cap the number of discovered items when running `--rebuild-queue`
- `--source-root`, `--wiki-root`, `--queue-file`, `--prompt-template`: override default paths
